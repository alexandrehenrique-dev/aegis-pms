# Etapa 06.1 — Hotfix: templates de e-mail de produto (productAssignment + productAccessRevoked)

> **Contexto de origem:** a etapa 06 foi executada antes da ADR-0020 (ciclo de vida do usuário) existir. A ADR-0020 define dois novos templates FreeMarker que são necessários pelas etapas 10 (`POST /products/{productId}/users` com `userId`) e 15 (remoção de `ProductAssignment`). Esta etapa mínima adiciona esses dois arquivos ao tema Keycloak já existente, sem tocar em nenhum código Java.
>
> Pré-requisito: etapa 06 concluída (tema `aegis` já existe em `infra/keycloak/themes/aegis/email/`).

## Objetivo

Criar os templates FreeMarker `productAssignment.ftl` e `productAccessRevoked.ftl` no tema de e-mail Aegis do Keycloak. Esses templates são usados diretamente via SMTP (não via `executeActionsEmail` do Keycloak Admin API) — o backend os renderiza com `FreeMarkerTemplateUtils` ou equivalente e envia pelo `JavaMailSender` configurado na etapa 06.

## Tarefas

### A. Arquivos a criar

```
infra/keycloak/themes/aegis/email/html/productAssignment.ftl
infra/keyclker/themes/aegis/email/html/productAccessRevoked.ftl
```

> **Atenção:** diferente de `executeActions.ftl` e `password-reset.ftl` (que são usados pelo Keycloak internamente para disparar e-mails com link de ação), estes dois templates são e-mails **informativos** enviados diretamente pelo backend Java via `JavaMailSender`. Por isso, podem ficar tanto no diretório do tema Keycloak (para centralização) quanto em `backend/src/main/resources/templates/email/` (mais comum para templates enviados por Spring). A decisão é do GPT que executar a etapa 10 — registrar no `SPRINT-RESULTADO.md`. O que importa é consistência: se usar o tema Keycloak, ambos ficam lá; se usar `resources/templates/`, ambos ficam lá.
